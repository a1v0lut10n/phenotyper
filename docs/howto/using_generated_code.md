# Using Generated Rust Code

This guide explains how to use the Rust code generated by the Phenotyper
compiler, including struct construction, builder pattern, rendering, and
working with plural wrappers.

## Overview

For each phenotype definition, the compiler generates:

| DSL Construct | Generated Rust |
|---------------|---------------|
| Phenotype `Foo` | `pub struct Foo` + `pub struct FooBuilder` |
| Plural `Foos` | `pub struct Foos` (wrapper) + `pub struct FoosBuilder` |
| Union type | `pub enum UnionName` |
| Enum type | `pub enum EnumName` |
| Render expressions | `impl Render for Foo` |

All generated code includes:
- `pub trait Render` with `render()` and `render_into()` methods
- `pub enum BuildError` for builder validation errors
- `#![allow(dead_code, unused_imports)]` for flexibility

## Struct Construction

### Direct Construction

Fields are public, so you can construct directly:

```rust
let entry = ConfigEntry {
    key: "host".to_string(),
    value: ConfigValue::String("localhost".to_string()),
    visibility: Visibility::Public,
};
```

### Builder Pattern

Every struct has a builder for validated construction:

```rust
let entry = ConfigEntryBuilder::new()
    .key("host".to_string())
    .value(ConfigValue::String("localhost".to_string()))
    .visibility(Visibility::Public)
    .build()?;  // Returns Result<ConfigEntry, BuildError>
```

The `build()` method validates that all required fields are set and
returns `Err(BuildError::MissingField("field_name"))` if any are missing.

## Rendering

Every generated struct implements the `Render` trait:

```rust
pub trait Render {
    fn render_into(&self, out: &mut String);

    fn render(&self) -> String {
        let mut buf = String::new();
        self.render_into(&mut buf);
        buf
    }
}
```

### Basic Rendering

```rust
let section = PromptSection {
    heading: "Rules".to_string(),
    body: "Be concise.".to_string(),
};

// Get the rendered string
let output = section.render();
assert_eq!(output, "## Rules\n\nBe concise.");

// Or render into an existing buffer
let mut buf = String::new();
section.render_into(&mut buf);
```

### Rendering with Optional Fields

Optional fields use `@ifset` in the DSL. In Rust, they are
`Option<T>` and the block renders only when `Some`:

```rust
let report = Report {
    title: "My Report".to_string(),
    subtitle: Some("Draft".to_string()),  // Renders subtitle block
    lines: ReportLines::from_vec(vec![
        ReportLine { content: "Line 1".to_string() },
    ]),
    tags: Tags::new(),     // Empty — @ifnotempty block omitted
    footer: None,          // None  — @ifset block omitted
};

let output = report.render();
// Contains: "# My Report\n## Draft\n\nLine 1"
// Does NOT contain: "Tags:" or "---"
```

## Plural Wrappers

Plural companions generate wrapper structs around `Vec<T>`:

```rust
pub struct Records {
    items: Vec<Record>,
}
```

### Creating Plural Wrappers

```rust
// Empty collection
let records = Records::new();

// From a vector
let records = Records::from_vec(vec![
    Record { name: "Alice".to_string() },
    Record { name: "Bob".to_string() },
]);

// Using the builder
let records = RecordsBuilder::new()
    .push(Record { name: "Alice".to_string() })
    .push(Record { name: "Bob".to_string() })
    .build()?;
```

### Collection API

```rust
let records = Records::from_vec(vec![...]);

records.len();              // Number of items
records.is_empty();         // True if no items
records.as_slice();         // &[Record]
records.iter();             // Iterator over &Record
records.into_vec();         // Consume and get Vec<Record>
```

### Rendering Plurals

Plural wrappers implement `Render`. When used with `@join`, items
are rendered with a separator between them:

```rust
let tags = Tags::from_vec(vec![
    Tag { label: "rust".to_string() },
    Tag { label: "dsl".to_string() },
]);

// If the phenotype uses @join(tags, ", ")
// Output: "rust, dsl"
```

## Union Types

Union types generate Rust enums:

```rust
pub enum ScalarValue {
    Int64(i64),
    Real64(f64),
    String(String),
    Date(String),
    Time(String),
    DateTime(String),
}
```

Construct with variant constructors:

```rust
let val = ScalarValue::Int64(42);
let val = ScalarValue::String("hello".to_string());
```

Union types implement `Render` and render their inner value using
`Display` for primitives or `render_into()` for user types.

## Enum Types

Enum types generate Rust enums that render their original DSL spelling:

```rust
pub enum Visibility {
    Public,    // renders as "public"
    Private,   // renders as "private"
    Internal,  // renders as "internal"
}
```

## Error Handling

The `BuildError` enum covers validation errors:

```rust
pub enum BuildError {
    MissingField(&'static str),
}
```

Handle in standard Rust fashion:

```rust
match result {
    Ok(record) => println!("{}", record.render()),
    Err(BuildError::MissingField(name)) => {
        eprintln!("required field '{}' was not set", name);
    }
}
```

## Nested Types with Parent Context

When a nested phenotype references a parent field (e.g., `@(JavaClass/name)`),
the compiler generates a `render_with_parent` method instead of using the
standard `render_into` from the `Render` trait.

### Generated API

```rust
impl Constructor {
    pub fn render_with_parent(&self, parent: &JavaClass, out: &mut String) {
        // Accesses parent.name for @(JavaClass/name)
        out.push_str(&parent.name);
        out.push_str("(");
        // ... rest of render body
    }
}
```

The standard `Render` trait is still implemented, but calling `render_into`
directly on a type that requires parent context will panic with a descriptive
message:

```rust
// This panics:
constructor.render();

// Use render_with_parent instead:
let mut buf = String::new();
constructor.render_with_parent(&java_class, &mut buf);
```

### When is `render_with_parent` Generated?

Only nested types that actually reference parent fields via `@(Parent/field)`
paths get `render_with_parent`. Nested types that don't reference parent
fields generate normal `render_into` like any top-level type.

### Usage Example

```rust
let java_class = JavaClass {
    name: "MyService".to_string(),
    visibility: Visibility::Public,
    super_class: None,
    ctors: Constructors::from_vec(vec![
        Constructor {
            arg_list: Some("String name".to_string()),
        },
    ]),
};

// Render the parent (which may internally call render_with_parent on children)
let output = java_class.render();

// Or render a child manually with parent context
let mut buf = String::new();
java_class.ctors.items[0].render_with_parent(&java_class, &mut buf);
// buf == "MyService(String name)"
```

## Integration Tips

1. **Add the generated module to your `mod.rs`** or use `include!`
2. **Generated code has no external dependencies** — it uses only `std`
3. **All fields are `pub`** — you can read and modify them directly
4. **`Clone` and `Debug` are derived** on all generated structs
5. **`Default` is derived on plural wrappers** and builder structs
6. **Nested types are flat in Rust** — they appear as independent structs,
   not Rust nested types
7. **Parent context is explicit** — use `render_with_parent` when the DSL
   uses `@(Parent/field)` references
