# Summary

Title: Phenotyper DSL and Plan

Synopsis: Concept and implementation plan for Phenotyper, a domain-specific language and code generator that defines output structures and programmatically builds and parses them to standardize and constrain outputs for AI-driven coding and prompt engineering.

Key Takeaways:

- Concept and purpose:

  - Phenotyper is based on genotype (definition) and phenotype (manifestation), defining output structures (e.g., source code, data, web pages) and generating APIs to construct conformant outputs.
  - Distinct from template engines by offering a human-friendly DSL where the output’s shape remains recognizable in the source, improving constraints and verifiability for LLM-driven generation.
  - Intended to standardize formats across different LLMs and over time, aiding agentic coding reliability (analogous in spirit to compile-time guarantees).

- Capabilities:

  - Generate builder-pattern APIs for constructing outputs per definitions.
  - Ideally also generate parsers to serialize/deserialize outputs, similar in concept to Protocol Buffers.

- DSL design:

  - Human-friendly, punctuation-driven specification language (non-whitespace-significant).
  - Punctuation semantics inspired by Prolog: comma = “and/continuation,” colon = introduce/define structure, semicolon = terminate definition and continue.
  - Phenotype naming before colon; includes verbatim blocks and typed variables (e.g., addressee: string).

- Implementation status and tooling:

  - Legacy implementation exists but is unsatisfactory; re-implementation underway in Rust.
  - Grammar for the output definition language already exists.
  - Parol was initially used but had limitations (lookahead, ambiguity); Rustemo is preferred for ambiguous, punctuation-heavy DSLs and has been successfully used in COLAP.

- Related work:

  - COLAP: a configuration language using colons, commas, periods, semicolons; implemented with Rustemo.

- Use cases:

  - Prompt engineering (Project Verbatim): define reusable, structured prompt formats for subtitling/transliteration across languages/dialects (e.g., Niederdeutsch/Berner Deutsch to Hochdeutsch).

- Bootstrapping strategy:

  - First iteration will generate code via a conventional template engine.
  - Transition to self-bootstrapping where Phenotyper generates its own generator.
